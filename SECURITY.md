# Безопасность

Автор: INew

## Ограничения исправления audit ACL

Операция v1.0.6 разрешена только в DEV для `platform-operator` на `sys/audit`.
Agent сам читает HCL, проверяет точные `list, read` и вычисляет добавление `sudo`.
Клиент не задаёт policy/path/HCL. Неоднозначная или ограниченная policy отклоняется.
Snapshot предшествует записи; hash перепроверяется перед ней. После единственной
попытки выполняются read-back и отзыв временного root, включая потерю HTTP-ответа.
Неизвестный исход не разрешает повторную запись. ACL API не имеет CAS, поэтому
параллельное внешнее редактирование должно быть исключено оператором.

## Что разрешено публиковать

В публичном репозитории находятся только `.md`, `.sh`, безопасные JSON/Nginx/systemd/logrotate-шаблоны, `.gitignore` и workflow проверки. Бинарный Agent размещается только в GitHub Release.

Запрещено публиковать:

- `.env`, файлы ответов и рабочий `agent.json`;
- пароли, TOTP, токены, SecretID, AppRole RoleID и root token;
- закрытые TLS-ключи, device CA key, клиентские PFX/PEM;
- state, journal, snapshot, backup, audit и log-файлы;
- реальные внутренние IP, OpenBao URL, policy и entity ID;
- исходный код OpenBao Manager или Control Agent.

Перед публикацией maintainer обязан запустить поставляемый verifier и проверить состав архивов. Закрытый ключ подписи в версии 1 не создаётся и не хранится в этом репозитории.

## Модель доступа

- Agent слушает только `127.0.0.1`.
- Внешний HTTPS завершает Nginx.
- Nginx перезаписывает `X-INew-Client-Cert` значением проверенного клиентского сертификата; входящий заголовок пользователя не считается доверенным.
- Публичными остаются только health/version и первичная pairing-операция; защищённые операции дополнительно проверяются Agent.
- DEV и PROD имеют разные пользователей, конфигурацию, device CA, состояние, аудит, резервные копии и сетевые порты.
- С v1.0.4 разрешены стандартные orphan service-токены Userpass. Они не имеют родительского токена и отзываются напрямую либо истекают по TTL. Разрешение не отменяет запрет root, проверку policies/entity ID, источника Userpass, TTL и устройства.
- Сетевые ограничения оператора не снимаются установщиком. С v1.0.5 Agent передаёт проверенный исходный IP и дополнительно проверяет bound_cidrs; до v1.0.5 IP-bound токены не поддерживались.
- Исходный IP доверяется только после проверки устройства и только от локального nginx: используется последнее значение X-Forwarded-For, добавленное прокси. Внешние значения слева не дают права на подмену IP.
- OpenBao должен доверять переданному IP только от проверенного локального прокси. Глобальные real_ip-настройки nginx и доступ недоверенных процессов к loopback требуют отдельной проверки. Listener OpenBao и ограничения пользователя не изменяются установщиком.
