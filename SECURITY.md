# Безопасность

Автор: INew

## Что разрешено публиковать

В публичном репозитории находятся только `.md`, `.sh`, безопасные JSON/Nginx/systemd/logrotate-шаблоны, `.gitignore` и workflow проверки. Бинарный Agent размещается только в GitHub Release.

Запрещено публиковать:

- `.env`, файлы ответов и рабочий `agent.json`;
- пароли, TOTP, токены, SecretID, AppRole RoleID и root token;
- закрытые TLS-ключи, device CA key, клиентские PFX/PEM;
- state, journal, snapshot, backup, audit и log-файлы;
- реальные внутренние IP, OpenBao URL, policy и entity ID;
- исходный код OpenBao Manager или Control Agent.

Перед публикацией maintainer обязан запустить поставляемый verifier и проверить состав архивов. Закрытый ключ подписи в версии 1 не создаётся и не хранится в этом репозитории.

## Модель доступа

- Agent слушает только `127.0.0.1`.
- Внешний HTTPS завершает Nginx.
- Nginx перезаписывает `X-INew-Client-Cert` значением проверенного клиентского сертификата; входящий заголовок пользователя не считается доверенным.
- Публичными остаются только health/version и первичная pairing-операция; защищённые операции дополнительно проверяются Agent.
- DEV и PROD имеют разные пользователей, конфигурацию, device CA, состояние, аудит, резервные копии и сетевые порты.

## Сообщение об уязвимости

Не публикуйте уязвимость и технические секреты в открытом issue. Используйте приватный канал владельца репозитория или GitHub Private Vulnerability Reporting, если он включён. Укажите версию, дистрибутив, воспроизводимые шаги и ожидаемое влияние без реальных credentials.
