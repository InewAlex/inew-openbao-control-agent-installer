# INew OpenBao Control Agent Installer

Автор: INew

Публичный установщик Linux-компонента, который связывает OpenBao Manager с локальным OpenBao через защищённый HTTPS-контур. В Git находятся только установщик, проверяющие скрипты и безопасные шаблоны. Исполняемый файл Agent публикуется отдельно в GitHub Releases.

## Что автоматизирует установщик

- устанавливает отдельный экземпляр для `dev` или `prod`;
- создаёт системного пользователя и закрытые каталоги;
- локально создаёт отдельный device CA выбранной среды;
- формирует точный `agent.json` без паролей и TOTP;
- настраивает и проверяет systemd, Nginx и logrotate;
- проверяет конфигурацию Agent до запуска;
- сохраняет существующие файлы и автоматически откатывает их при ошибке;
- при первой установке показывает одноразовый код привязки к OpenBao Manager.

Сайты и Laravel-проекты могут находиться на других серверах. Agent устанавливается на сервере, где OpenBao доступен через loopback-адрес `127.0.0.1`.

## Поддерживаемые системы

- Ubuntu Server 22.04 и 24.04;
- Debian 12 и 13;
- архитектура `x86_64`;
- systemd, Nginx, OpenSSL, curl и стандартные GNU-утилиты;
- OpenBao 2.6.x.

## Простая установка

1. Откройте раздел **Releases** этого репозитория.
2. Скачайте asset `inew-openbao-control-agent-v<версия>-linux-x64.tar.gz`.
3. Сверьте SHA-256 архива со значением, опубликованным владельцем в описании Release.
4. Распакуйте архив и откройте полученный каталог.
5. Запустите:

```bash
sudo ./install.sh
```

Установщик задаст девять понятных вопросов. Пароли OpenBao, TOTP, root token и секреты проектов он не запрашивает и не сохраняет.

Не запускайте установку конструкцией `curl | bash`: сначала скачайте и проверьте архив.

## Какие данные понадобятся

| Поле | Что означает |
|---|---|
| Среда | `dev` или `prod`; за один запуск устанавливается одна среда |
| Публичное DNS-имя | HTTPS-адрес, по которому Windows-программа увидит Agent |
| Порт Agent | Локальный порт; по умолчанию 9120 для DEV и 9130 для PROD |
| Порт OpenBao | Локальный порт; по умолчанию 8200 для DEV и 8300 для PROD |
| TLS-сертификат | Уже существующий сертификат публичного DNS-имени |
| TLS-ключ | Уже существующий закрытый ключ этого сертификата |
| Policies | Разрешённые policy учётной записи оператора OpenBao |
| Entity IDs | Разрешённые entity ID операторов OpenBao |
| TTL | Минимальный оставшийся срок действия токена, обычно 300 секунд |

Policy и entity ID не являются паролями, но описывают внутреннюю структуру доступа. Не публикуйте заполненный файл ответов.

## Установка через закрытый файл ответов

Для повторяемой установки создайте на сервере `/root/agent-install.env`, принадлежащий `root` с правами `0600`:

```dotenv
INEW_ENVIRONMENT=dev
INEW_PUBLIC_HOST=agent-dev.example.com
INEW_AGENT_PORT=9120
INEW_OPENBAO_PORT=8200
INEW_TLS_CERTIFICATE_PATH=/etc/letsencrypt/live/agent-dev.example.com/fullchain.pem
INEW_TLS_PRIVATE_KEY_PATH=/etc/letsencrypt/live/agent-dev.example.com/privkey.pem
INEW_OPERATOR_POLICIES=replace-with-operator-policy
INEW_OPERATOR_ENTITY_IDS=replace-with-operator-entity-id
INEW_MIN_OPERATOR_TTL_SECONDS=300
```

```bash
sudo chmod 0600 /root/agent-install.env
sudo ./install.sh --answers /root/agent-install.env
```

Файл разбирается как данные, а не исполняется как shell-скрипт. Не добавляйте в него пароли, TOTP, токены, SecretID или секреты проектов.

## После установки

При первой установке скопируйте показанный одноразовый код в OpenBao Manager и завершите привязку соответствующей среды. Для второго контура повторно запустите установщик с другими DNS-именем, портами, policy и entity ID.

Диагностика, обновление и ручное создание нового pairing-кода описаны в [RELEASE.md](RELEASE.md). Правила безопасной публикации и сообщения об уязвимостях — в [SECURITY.md](SECURITY.md).

## Ограничение версии 1

Целостность бинарного файла проверяется SHA-256. В первой версии нет цифровой подписи издателя и автоматического сетевого обновления. SHA-256 внутри архива обнаруживает повреждение, но сам по себе не доказывает авторство архива.
